### 01. Next.js 프로젝트 구조와 App Router 핵심 철학

```
    **Next.js 프로젝트 구조**는 단순한 파일 배치가 아니라, 프레임워크가 제시하는 **"반드시 지켜야 하는 개발 표준과 규칙(법전)"**입니다.
```

1. 루트 설정 파일 (프로젝트의 뼈대)

- 주요 파일 역할:

```
- package.json (주민등록증): 프로젝트 정보 및 의존성 외부 라이브러리 목록, 명령어(Script) 정의.
- tsconfig.json (엄격한 감독관): TypeScript 컴파일러 설정 (임의 수정 시 에러 발생).
- tailwind.config.ts (디자인 시스템 설정집): 색상, 폰트 등 스타일링 규칙 정의.
- eslint.config.mjs (코드 경찰관): 코드 품질 검사 설정 (최신 Flat Config 형식).
- next.config.ts (중앙 관제탑): Next.js 서버 동작 제어 및 이미지 최적화 도메인 설정.

```

2. App Router의 심장: src/app과 절대 규칙

```
- page.tsx (가게 간판): 해당 경로의 유일한 UI를 담당. 반드시 소문자 page.tsx여야만 화면이 렌더링됨.
- layout.tsx (인테리어 골조): 공통 UI(껍데기)를 정의하며 상태 유지 및 SEO 메타데이터 설정. (<html>, <body> 태그 필수 포함)

```

```javascript
// app/layout.tsx
// 이 파일은 애플리케이션의 최상위 레이아웃(Root Layout)입니다.

import type { Metadata } from "next";
import "./globals.css";

export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    // ⚠️ 주의: html과 body 태그는 오직 'Root Layout'에만 존재해야 합니다!
    <html lang="en">
      <body>
        {/* 1. 네비게이션 바: 여기에 배치하면 모든 페이지에서 유지됩니다. */}
        <nav className="p-4 bg-gray-100">
            My Navbar (공통 영역)
        </nav>

        {/* 2. Main Content: 우리가 만든 page.tsx가 이 'children' 자리에 렌더링됩니다. */}
        <main>{children}</main>

        {/* 3. 푸터: 여기에 배치하면 모든 페이지 하단에 고정됩니다. */}
        <footer className="p-4 bg-gray-800 text-white">
            My Footer (공통 영역)
        </footer>
      </body>
    </html>
  );
}

```

3. Colocation (위치 병합): 혁신적인 파일 관리

- 관련된 코드를 멀리 두지 않고 같은 방(폴더)에 함께 모아둔다 라는 Next.js App Router의 핵심 파일 관리 철학

| 비교 항목         | 과거 방식 (Pages Router)                     | 현재 혁신 방식 (App Router)                     |
| ----------------- | -------------------------------------------- | ----------------------------------------------- |
| **파일 노출**     | 폴더 내 모든 파일이 곧바로 URL 주소가 됨     | 오직 `page.tsx`만 라우트(주소)로 인식           |
| **컴포넌트 관리** | 부품용 컴포넌트를 숨기기 위해 별도 폴더 필요 | `page.tsx`와 같은 방(폴더)에 안전하게 공존 가능 |

4. public 폴더: 정적 자산의 창고

- 외부로 공개된 정적 자산(Static Assets)을 보관하는 창고
- 용도: 이미지(.png, .jpg), 폰트, robots.txt, favicon.ico 등
- 접근 방식:public 폴더 내에 logo.png를 넣었다면, 브라우저 주소창이나 코드에서 /logo.png로 바로 접근합니다.

```javascript
// 예시: public/logo.png 파일을 사용하는 코드
import Image from "next/image";

export default function Page() {
  return (
    // 별도의 import 없이 절대 경로 '/'로 바로 접근
    // 여기서 '/'는 public 폴더를 의미합니다.
    <Image src="/logo.png" alt="Logo" width={100} height={100} />
  );
}
```

5. 핵심 요약 (Core Summary)

- 명명 규칙 준수:page.tsx와 layout.tsx는 대소문자까지 정확히 지켜야 하는 시스템 파일

- Root Layout의 책임: 최상위 레이아웃은 반드시 <html>과 <body> 태그를 포함해야 합니다. 다른 레이아웃은 html, body 태그를 포함해서는 안된다.

- Colocation의 이점: 부품 컴포넌트를 page.tsx와 같은 폴더에 두어 관리 편의성을 극대화

- 상태 유지: 레이아웃은 페이지 이동 시에도 언마운트되지 않아 검색어 입력값이나 스크롤 위치 등을 보존하기 유리

- Public의 역할:/ 경로로 시작하는 모든 정적 파일(이미지 등)은 public 폴더를 참조

### 02.File-system Routing과 중첩 레이아웃(Nested Layout)

```
**파일 시스템 라우팅(File-system Routing)**은 별도의 복잡한 라우터 설정 파일 없이, **올바른 위치에 폴더와 파일을 생성하는 것만으로 URL 주소가 완성되는** Next.js의 강력한 라우팅 시스템입니다.
```

1. 첫 번째 페이지 만들기 (/about)

- 핵심 규칙:

```
- 경로 매핑: src/app/about 폴더 생성 시 브라우저 주소는 자동으로 /about이 됩니다.
- 파일명 규칙: 반드시 소문자 page.tsx여야 합니다 (About.tsx나 Page.tsx는 404 에러 발생).

- Export 규칙: 자유로운 함수 이름 사용이 가능하지만 반드시 export default를 사용해야 합니다.

- Fast Refresh: 코드를 저장하면 서버 재시작 없이 브라우저에 즉시 반영됩니다.

```

2. 중첩 레이아웃(layout.tsx)의 적용

```
- 공통 UI 관리: 특정 섹션(예: About)에서만 공통으로 유지되어야 하는 네비게이션, 사이드바 등을 관리합니다.

- children Prop: 레이아웃 컴포넌트는 반드시 하위 page.tsx 내용이 주입되는 children 슬롯을 포함해야 합니다.
```

```javascript
/* ✅ [실습 코드] src/app/about/layout.tsx */
export default function AboutLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <section className="border-4 border-blue-500 m-4 p-4 rounded-lg">
      <nav className="bg-blue-100 p-4 mb-4 rounded">
        <h2 className="text-xl font-bold text-blue-800">🏢 About 섹션 전용 네비게이션</h2>
      </nav>
      {/* page.tsx의 내용이 들어가는 자리 */}
      <main className="bg-white">{children}</main>
    </section>
  );
}
```

3. 레이아웃 중첩의 미학: 샌드위치 조립 방식

- localhost:3000/about/company 접속 시 조립 순서:

```
- 1단계: 가장 바깥쪽의 Root Layout (src/app/layout.tsx) 적용

- 2단계: 그 위에 About Layout (src/app/about/layout.tsx) 얹기

- 3단계: 가장 안쪽에 Company Page 내용 채우기

```

### 03. Next.js 레이아웃의 불변성

1. 전통적인 HTML 기반 웹사이트와 Next.js의 가장 큰 차이점

- 기존 방식 (HTML): 메뉴를 클릭하면 화면 전체가 하얗게 깜빡이며 새로고침됩니다. 사이드바에 검색어를 입력했거나 스크롤을 내려놓았더라도, 페이지 이동과 동시에 모든 정보가 초기화

- Next.js 방식: 레이아웃 컴포넌트는 최초에 딱 한 번만 렌더링됩니다. 이후에는 고정된 채 오직 알맹이에 해당하는 page.tsx만 갈아 끼워집니다. 마치 TV의 프레임(테두리)은 그대로 둔 채 화면 속 영상만 바뀌는 것

2. 핵심 요약 (Core Summary)

- 레이아웃 상태 유지 (Preserving State): 페이지가 전환되어도 layout.tsx는 언마운트(Unmount)되지 않습니다. 덕분에 입력 폼의 텍스트, 스크롤 위치, 비디오 재생 상태 등이 그대로 보존됩니다

- 부분 렌더링 (Partial Rendering): 변경된 하위 children 페지만 서버에서 받아와 교체합니다. 전체 페이지를 다시 불러오지 않으므로 깜빡임이 없고 속도가 매우 빠릅니다.

- 클라이언트 사이드 내비게이션: <Link> 컴포넌트를 사용하면 브라우저의 기본 이동 방식이 아닌, 앱처럼 부드러운 화면 전환 UX를 제공

- 독립적 스크롤 제어: 레이아웃 구조 내에서 overflow-y-auto를 적절히 배치하면, 사이드바는 고정하고 본문만 스크롤하는 실무적인 대시보드 레이아웃을 쉽게 구현
